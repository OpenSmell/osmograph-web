Osmograph Docs

Introduction

Osmograph is a desktop application for digital olfaction — the measurement and identification of odours using an array of Metal Oxide (MOX) gas sensors. It connects to an ESP32-based electronic nose, records sensor responses, extracts 187-dimensional feature vectors, and classifies substances in real time.

What Problem Does This Solve?

Traditional gas sensing is device-dependent: a reading from one sensor board cannot be compared to another. Osmograph solves this through the Rs/R0 normalization pipeline, which mathematically cancels supply voltage and load resistor variations, producing device-agnostic feature vectors. This means:

  • Models trained on one device work on another (same sensor model)
  • Features are physically interpretable across rigs
  • You can share and compare datasets across labs

Five Feature Dimensions

DimensionQuestionExample Features
Device-AgnosticWhat substance?Relative amplitude, rise time, AUC
AbsoluteWhat concentration?Raw resistance, voltage, calibrated concentration
TemporalHow fast?Transient response, oscillation frequency
HealthIs the sensor working?Drift rate, sensitivity decay, noise floor
HardwareWhich device?Circuit response, thermal profile, ADC noise

Quick Start

# Install dependencies
pip install -r requirements.txt

# Run Osmograph
python -m Osmograph

# Or from the repo root:
python run_osmograph.py

What You'll Need

  • An ESP32 development board
  • 1–6 MQ-series gas sensors (MQ-135, MQ-3, MQ-6, MQ-7, MQ-4, MQ-8)
  • USB cable for flashing and serial connection
  • Breadboard and wiring (see Hardware Setup)

First Launch

  1. Connect your ESP32 via USB
  2. Click Detect Board in the toolbar
  3. Select your sensor preset
  4. Click Flash Firmware (one-time)
  5. Click Connect to start receiving data

The dashboard will show live sensor traces. Allow 24 hours of burn-in for new MQ sensors to stabilise.

Hardware Setup

Wiring

Each MQ sensor has 4 pins: VCC (5V), GND, DO (digital out — not used), and AO (analog out). Connect AO to an ESP32 ADC pin, VCC to 5V, and GND to common ground.

A 1kΩ load resistor (RL) is typically built into the sensor module. If not, add one between AO and GND.

Use the Pin Mapper dialog (Tools menu) to customise pins and export a PlatformIO sketch.

Presets

The app ships with presets for 2–6 sensors. Select the preset matching your hardware when flashing. Custom presets can be added to sensor/presets.py.

Connecting

USB Serial

  1. Plug in your ESP32
  2. Click Detect Board — it auto-detects known ESP32 boards
  3. Select the port from the dropdown
  4. Click Connect

WiFi

The ESP32 firmware also creates a WiFi access point (SSID: OSMOGRAPH-XXXX).

  1. Switch mode to WiFi in the toolbar
  2. Click Discover WiFi (uses mDNS) or enter the IP
  3. Click Connect

Data Format

The device sends lines of the format: OSM,<adc0>,<adc1>,... at ~10 Hz over serial or TCP (port 8080).

Dashboard

The Dashboard is the main workspace (first tab). It is divided into two panels:

  • Left (main): Live sensor trace graph with a collapsible fingerprint radar below
  • Right panel: Signal quality, device health, substance prediction, and competition grid

Toolbar Controls

  • FP button: toggle fingerprint visibility
  • Reset: clear all traces, predictions, and quality data
  • Pause/Resume: freeze the live trace display

The signal quality indicator shows a compact dot with status (Warming Up / Ready / Recording). Per-sensor stability is shown as coloured dots (green/yellow/red) on the right edge of the trace graph. The device health widget shows per-channel noise and drift metrics once enough samples are collected.

Tab Layout

Osmograph organises its interface into 3 main tabs, each with sub-tabs for secondary functions:

  • Dashboard — live sensor monitoring (this view)
  • Recordings — Browse (import/manage), Train (classifier training), Adapter (lightweight training)
  • System — Settings (connection, classifier config), Burn-In, Plugins

This reduces toolbar clutter and groups related functionality together.

Live Traces

The trace graph displays real-time sensor readings with 6 colour-coded lines. Each sensor has a dedicated colour:

SensorColour
MQ-135Cyan
MQ-3Magenta
MQ-6Lime
MQ-7Tomato
MQ-4Gold
MQ-8Turquoise

The Y-axis shows Rs/R0 (normalised resistance). A response is a downward or upward deflection depending on sensor type (n-type vs p-type).

A column of small coloured dots on the right edge shows per-sensor signal quality:

  • Green = stable (>80% stability)
  • Yellow = moderate (50–80%)
  • Red = unstable (<50%)

Fingerprint

The radar chart below the traces shows a fingerprint — a compact visual summary of the current sensor response. Toggle visibility with the FP button in the dashboard toolbar.

Dual Modes

Click the Sensor / Feature toggle button on the fingerprint widget to switch between:

  • Sensor mode (default): 6-axis radar showing each MQ sensor's normalised response amplitude. This is the raw "who's responding" view.
  • Feature mode: 8-axis radar showing derived features: Amplitude, Rise Time, Decay Time, AUC, Endpoint, Saturation, Selectivity, and Channel Activity.

Export

Export the full 187-dimensional feature vector via File → Export Fingerprint (Ctrl+E). Supports JSON (with metadata) and CSV formats.

Device Health

The device health widget appears in the Dashboard's right panel once enough samples (>20) are collected. It shows per-channel health metrics for each sensor:

  • Coloured dot: Green = stable (noise <0.5), Yellow = moderate, Red = noisy/unstable
  • Status label: "OK", "~" (marginal), or "!" (poor)

The widget auto-hides when no data is available. Health metrics (noise floor, drift rate, stability) are computed from the most recent 100 samples in real time.

Prediction Panel

The prediction panel (right side, below signal quality) shows the substance identification result:

  • Substance name — the predicted class label
  • Confidence score — 0.0 to 1.0, shown numerically and as a progress bar
  • Warning — shown if confidence is low or the sample is out of distribution

When the classifier is confident (>70%) for 10 consecutive predictions, the prediction locks (shown with a border). Below 50%, the sample is flagged as Unknown after 20 low-confidence predictions.

Demo Mode

Osmograph includes a Demo mode that generates synthetic sensor data — no hardware required. This is useful for:

  • Testing the UI and layout without connecting a board
  • Evaluating classifier behaviour with simulated inputs
  • Demonstrations and presentations
  • Verifying theme toggle and layout responsiveness

How to Use

  1. Click the Demo button in the toolbar (next to Connect)
  2. The button turns yellow and shows "Stop Demo"
  3. Synthetic sine-wave data appears in the trace graph
  4. Click "Stop Demo" to end the simulation

Demo mode uses six sinusoidal signals with added Gaussian noise to simulate sensor responses. If a classifier is loaded, predictions run against the synthetic data in real time.

Competition Grid

The competition grid shows all class probabilities simultaneously as animated vertical bars. Each bar represents one substance class:

  • Bar height = probability (0–100%)
  • Bar colour = class-specific colour
  • Percentage label above each bar
  • Class name rotated below

When locked, a dashed accent border appears around the grid. The grid updates at 33ms intervals with smooth interpolation.

Recordings Tab

The Recordings tab is the central hub for managing your data. It has three sub-tabs: Browse, Train, and Adapter.

Browse

The Browse sub-tab lists all recorded sessions. Each recording is stored as a CSV file with a corresponding metadata entry.

  • Import CSV: import an external CSV recording (useful for analysing data from other sources or sharing sessions between rigs)
  • Refresh: reload the session list from disk
  • Filter: filter by substance label
  • Process: run OpenSmell feature extraction and classification on a selected recording
  • Export FP: export the full 187-dimensional fingerprint as JSON or CSV
  • Delete: remove a recording permanently

Auto-Processing

When a new recording completes, Osmograph automatically processes it through the OpenSmell SDK, extracting features and updating the dashboard fingerprint, prediction, and sensor response display.

Train

See Classifier Training for details on training real-time classifiers from your recordings.

Adapter

See Adapter Wizard for lightweight adapter training.

Classifier Training

The Train sub-tab (under Recordings → Train) lets you train a real-time substance classifier from your recordings.

Workflow

  1. Record 3–5 samples of each substance (10–60 seconds each)
  2. Go to Recordings → Train — your recordings are loaded automatically
  3. Assign labels to each recording
  4. Choose a classifier model (RandomForest or LogisticRegression)
  5. Click Train Classifier
  6. The trained model appears in the toolbar dropdown — select it for real-time prediction

Models

ModelBest For
RandomForestGeneral purpose, handles non-linear separations, small datasets (5–50 samples per class)
LogisticRegressionFast, interpretable, works well when classes are linearly separable in feature space

Trained models are saved as .pkl files in the classifiers/ directory.

System Tab

The System tab (third main tab) groups configuration and maintenance tools into three sub-tabs: Settings, Burn-In, and Plugins.

Settings

System → Settings Configure serial baud rate, classifier parameters, and data storage directory.

  • Baud rate: 9600 to 921600 (default 115200)
  • Window size: sliding window for feature extraction (20–500 samples). Lower = faster updates, higher = more stable predictions.
  • Confidence threshold: below this value, predictions show as "Unknown" (0.0–1.0)
  • Save directory: where recorded CSV sessions are stored

Burn-In

System → Burn-In New MOX sensors require a burn-in period (typically 24 hours) to stabilise their baseline resistance.

  • Persistent across app restarts (saves to QSettings)
  • Power-loss detection: if the app was closed, elapsed time is preserved
  • Adjustable duration (1–168 hours)
  • Start / Stop toggle button with Resume support
  • Progress bar with HH:MM:SS countdown
  • When complete, sensors are marked as ready in the signal quality indicator

Plugins

System → Plugins Osmograph supports a plugin system for extending predictions. Plugins are Python scripts or model files dropped into the plugins folder (~/.config/Osmograph/plugins/).

Each plugin exposes a run(latent_vector) -> dict function called on every prediction. The latent vector is the 187-dimensional feature vector.

Example plugin:

def run(latent_vector):
    return {"custom_score": float(latent_vector.mean())}

Use the Plugins sub-tab to discover, load, and reload plugins.

Python SDK API

The opensmell Python package provides the core feature extraction and classification engine.

Basic Usage

import opensmell
result = opensmell.process("recording.csv")

# Access results
print(result.substance)        # "garlic"
print(result.confidence)       # 0.94
print(result.warning)          # "" or "Low confidence..."
print(result.chemoprint[:5])   # First 5 of 29-dim chemoprint
print(result.features[:10])    # First 10 of 187 feature values
print(result.feature_names[:5]) # ["ch0_da_relative_amplitude", ...]

Feature Extraction

from opensmell.features import (
    extract_all_framework_features,
    compute_multi_exp_decay,
    compute_saturation_index,
)

raw = opensmell.load_recording("recording.csv")
features = extract_all_framework_features(raw)
# Returns dict of 187 feature_name -> value

Normalisation

from opensmell.preprocessing import rs_r0_normalize
normalised = rs_r0_normalize(raw_voltages, baseline_samples=30)
# R_s / R_0 — mathematically cancels V_cc and R_L

Command Line

python -m opensmell path/to/recording.csv

Recording Protocol

For reliable temporal features, follow this recording protocol:

PhaseDurationDescription
Baseline30–60 sSensor in clean air to establish R0
Exposure30–60 sIntroduce the odour source near the sensor inlet
Recovery60–180 sReturn to clean air; sensor recovers to baseline

Tips for Good Recordings

  • Use a consistent distance from odour source to sensor inlet
  • Avoid cross-contamination between samples (ventilate between recordings)
  • Record at least 3 samples per substance for classifier training
  • Label immediately after recording while the sample context is clear
  • Monitor the signal quality indicator — wait for "Ready" before exposing

Troubleshooting

Board not detected

  • Check the USB cable (data, not charge-only)
  • Install USB-to-serial drivers (CP2102 / CH340)
  • On Linux, add your user to the dialout group: sudo usermod -a -G dialout $USER
  • Try a different USB port

No data appearing on traces

  • Verify the board is flashed with Osmograph firmware
  • Check the baud rate matches between firmware and app (default: 115200)
  • Try reconnecting
  • If using WiFi, verify the ESP32's IP address

Noisy or erratic sensor readings

  • Sensors may need burn-in (24h for new MQ sensors)
  • Check wiring: stable power, secure connections
  • Keep sensors away from drafts and airflow
  • RL value may need adjustment for your sensor model

Classifier training fails or performs poorly

  • Record at least 3 samples per substance
  • Ensure each recording follows the full protocol (baseline + exposure + recovery)
  • Verify sensor signals are stable (signal quality shows "Ready") before exposing
  • Try both RandomForest and LogisticRegression

Fingerprint export is empty

  • Process the recording with OpenSmell first (Recordings → Browse → Process)
  • Ensure the recording has sufficient samples (at least 50)

FAQ

Can I use this with sensors other than MQ series?

Yes, any analog gas sensor with a voltage output can be connected to the ESP32 ADC pins. The Rs/R0 normalisation is sensor-agnostic. You may need to adjust the load resistor and create a custom preset.

Does it work with 3 sensors instead of 6?

Yes. Use the Pin Mapper to configure your sensor count. The UI adapts: traces show only the active sensors, features are computed only for populated channels, and the fingerprint radar adjusts its axes.

Can I share my trained classifier with others?

Yes, classifiers are device-agnostic thanks to Rs/R0 normalisation. A model trained on one rig works on another (same sensor models). Share the .pkl file.

What is the difference between Osmograph and the OpenSmell SDK?

The SDK (opensmell) is the core feature extraction and classification engine — a pure Python library with no GUI. Osmograph is the full desktop application that provides the UI, device connectivity, recording, and visualisation on top of the SDK.

Is there a web version?

Not yet. Osmograph is a desktop application built with PySide6. A web/Streamlit platform is on the roadmap.

How is this different from a commercial electronic nose?

Osmograph is open-source, device-agnostic, and built on a mathematically proven normalisation framework. Commercial e-noses are expensive, proprietary, and produce device-specific readings that cannot be compared across units. Osmograph solves the interoperability problem that has limited digital olfaction to lab settings.
